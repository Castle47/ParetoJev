# EMER + Jev 增量实验

日期：2026-10-13。主问题：在相同行为模型、候选、监督和训练预算下，增加真实 Jev 输入能否改善 EMER 的推荐排序。

## 实现身份

依据 [EMER 论文 v2](https://arxiv.org/html/2508.05093v2) 独立实现候选比较 Transformer、行为分数 NormalizedRanks、反馈数量排序监督、逐行为目标的先验排序损失，以及上一模型/当前模型的 Mean@K 比值权重。原有 `EMERLikeReranker` 完整保留；新实现为 `EMERReranker`，不再用目标损失 EMA 代替上一模型比较。

这是 **EMER 的公开数据适配实现**。真实未曝光候选池、线上连续更新版本和观看时长预测不可得：使用已曝光伪候选组、上一 epoch 快照和 long_view 二值反馈；不声称完成原工业系统复现，也不将视频总时长当作预测观看时长。论文的 IPUT 指标因缺少 p_watchtime 暂未实现。

## 两组输入与监督

共同输入为 65 维候选特征编码、7 个冻结行为概率、7 个行为分数候选内平均排名、视频历史热度和用户累计曝光量，共 81 维。新增 Jev 块为 7 个 Choice 分数、7 个候选内排名、7 个归一化熵和 7 个 `1-熵` 代理，共 28 维。两个网络均保留 109 维接口；基线在任何计算之前将 Jev 块置零，保证尺寸、初始参数和主干一致。多余通道不意味着基线获得了 Jev 信息。

新实现输出单一排序分数，未增加原论文未规定的运行时偏好 FiLM。用户/视频 ID 只用于关联和统计，不作为 embedding 输入；输入字段和编码规则沿用既有 26 字段公开数据协议。全部历史严格早于同一候选组的最早曝光时间。

后验监督为六个正反馈 bit 数量减去 hate bit；有差异的候选构成 logistic 排序对，相同计数不强行排序。先验监督只使用冻结行为概率的候选顺序，负反馈以 `1-p_hate` 定向。两组均不把 Jev 当标签或新增教师损失。每组按逆抽样包含概率加权，权重归一化到训练均值一。

自进化权重采用每组、每目标的上一 epoch/当前模型前 3 名行为 utility 均值之比；只对分母分子加 1e-6 防零，不以真实测试反馈算权重。网络比较前采用 eval，训练前恢复 dropout。

## 数据与实验注册

`configs/emer_jev.json` 在新测试候选准备及模型预测之前登记。

- 开发训练：旧核心实验 4 月 20 日的 1,000 组。
- 开发验证：4 月 21 日 00:00–12:00 的 400 组。这是已经使用过的开发数据。
- 旧核心实验的 600 组测试数据完全排除在本次训练和选择之外。
- 新确认测试：4 月 22 日全天，完整后期标准日志中的 600 组；同场景、10 个不同候选、5 分钟以内、用户内不重叠。不是线上原始召回集合。
- 在 hate/follow/forward/comment/like/other 分层内随机抽样 60/60/60/60/120/240 组，保留总体数与包含概率，评价使用逆包含权重。它修正本实验抽样，不修正平台曝光偏差。
- 行为模型与校准器保持冻结；热度也沿用 4 月 20 日前的冻结计数，避免新增变量。
- 训练特征的标准化仅拟合训练集；常量字段尺度设为 1，修复旧流程一天训练时星期字段被放大百万倍的问题。
- 每组模型在种子 7/17/29 上执行相同的 4 个配置、30 epochs；学习率 0.001/0.0003、先验系数 1/0.25。各臂各种子通过加权验证六正向目标平均 NDCG@3 选择配置及 checkpoint，最早并列，初始化可选。所有训练结束后才对新测试集预测。

Jev 使用固定 `autotrust/JEV-27B` revision、七个 Choice 问题；本次新测试预算为 4,200 成功判断、最多 4,620 HTTP 尝试、单请求并发和最少 1 秒间隔，失败不替换样本。开发部分复用原始真实分数。Choice 是组内选择分布，不能叫独立点击率。最近 10 次曝光文本、候选 caption/封面文字和视频总时长输入 Jev，不发送真实反馈，不使用图片。

## 判定和统计

主指标为真实反馈的 long_view NDCG@3。预先登记以下效果条件：种子平均增益的配对用户 bootstrap 95% 区间下界 >0、三个种子主指标均提高、六正向目标平均增益区间下界 ≥0、点击 NDCG 退步下界不低于 -0.005、无 hate utility 退步下界不低于 -0.005。后两项是本实验提前设定的绝对 0.5 个百分点非劣容限，非工业标准。

使用 2,000 次配对用户重抽样，对固定三个种子的指标求均值。区间条件于这些已训练 checkpoint，不能当成跨训练总体的显著性证明。全部七个指标和每个种子结果保留；不改门槛、不按测试选模型，不以主指标替换业务在线收益。若效果条件未通过，报告失败或证据不足，不强行宣布 Jev 有效。

## 延迟与成本

分别记录七次 Jev HTTP 实际耗时及服务返回推理时间、真实请求次数，以及缓存分数已就绪时本地 CPU 排序模块 p50/p95/p99。固定候选数 10、batch 1、四 CPU 线程，两臂交替测量。

本地测量从准备好的张量到分数和排序，排除特征获取、序列/文本构建、网络 Jev 调用。不得称为完整推荐 RT，不得把小模块耗时冒充 Jev 接入耗时。当前未给定部署硬件、并发和业务新增 RT 预算，无法验收生产延迟，也无法确认线上业务收益。

## 执行

```bash
.venv/bin/python scripts/prepare_emer_jev.py --root data/raw/kuairand-27k --output data/raw/kuairand-27k/emer-jev-v1
.venv/bin/python scripts/run_emer_jev.py --root data/raw/kuairand-27k --output data/raw/kuairand-27k/emer-jev-v1 --stage develop
.venv/bin/python scripts/score_emer_jev.py --data data/raw/kuairand-27k/emer-jev-v1
.venv/bin/python scripts/run_emer_jev.py --root data/raw/kuairand-27k --output data/raw/kuairand-27k/emer-jev-v1 --stage confirm
.venv/bin/python scripts/run_emer_jev.py --root data/raw/kuairand-27k --output data/raw/kuairand-27k/emer-jev-v1 --stage replay
```

准备数据和训练可并行运行，使用不同锁并只共享确定性训练特征规范。模型、原始请求/响应、来源哈希、包含权重和预测保存到外接盘；最终结果写入报告，现阶段不预填成功结论。
