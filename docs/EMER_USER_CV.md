# 预算内的回溯性用户留出验证

用户维持累计65元上限后，继续使用已取得的36,000组、252,000项真实Jev判断在本机验证原完整EMER架构。没有新增API调用、GPU租用或假信号，也不重新解释未打分的Apr23-25独立测试为已完成。

## 固定协议

- 输入仅Apr19-21已有开发数据，12,606名用户；Apr23-25数据完全不进入此脚本。
- 三折外层用户留出；每个用户的所有列表只属于同一个外层测试折。
- 每折剩余用户按独立固定哈希分训练/内层验证。标准化只拟合内层训练候选。
- EMER与EMER＋Jev在每折、每个种子使用相同初始化和四组超参数，各训练30轮。共72次从头拟合，不复用见过外层用户的旧重排器权重。
- 所有拟合及内层选模完成后，才计算外层指标。每条列表最终恰有一组折外预测；不根据效果重新划分用户或挑折报告。
- 主目标仍为六正向NDCG@3均值，负反馈单独报告，保留全部七目标、各种子和各折结果。

## 证据边界

这能检验固定训练流程在未参与该折重排器训练和选模的用户上的表现，比直接报告选模验证集更有信息。但本数据此前已经被探索，不能声称是全新的前瞻性确认；也不能代替新日期泛化或线上A/B。

冻结行为模型可能在Apr19之前见过这些用户，因此这里只声称重排器用户隔离，不把它称为整个推荐系统的纯冷启动。

配对用户bootstrap仅总结已训练的折外预测。各折训练集重叠，不把折数或种子数冒充独立样本量，也不称这些区间为完整算法训练方差的无偏估计。任何正向结果都必须同时展示这些限制，不能自动作为目标完成证明。

方法参考：[Cawley与Talbot，选模与评价偏差](https://www.jmlr.org/beta/papers/v11/cawley10a.html)、[Bengio与Grandvalet，交叉验证方差限制](https://www.jmlr.org/papers/v5/grandvalet04a.html)。

## 执行

协议：`configs/emer_user_cv_v1.json`。脚本：`scripts/run_emer_user_cv.py`，阶段为prepare/train/evaluate/replay。新训练和内部特征编码均来自冻结注册；已有完整trial按哈希验证后复用，不能重复启动已有进程。

本地输出：`emer-jev-scale-v3/user-cv-v1/`；训练日志：`user-cv-v1-train.log`；自动评价日志：`user-cv-v1-evaluate.log`。两个计算线程，一次只运行一个trial。训练预计需要数小时，取决于本机负载。

`finish_emer_user_cv.sh`等待训练结束，检查完整selection后自动计算外层结果、独立进程重放并生成`reports/emer-user-cv-v1/README.md`。尚未有外层结果时不得根据内层训练日志下成功结论。
