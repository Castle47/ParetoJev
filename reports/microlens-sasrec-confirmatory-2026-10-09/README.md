# 固定 20% Jev 融合的新评价用户确认

本轮检验此前开发结果能否在 **700 名从未参与评价的用户** 上复现。
注册与实现已在训练、Jev 采集和测试指标计算之前提交为 `8a4b708`。
实验已完成；完整结果为 1/2 项确认要求通过，目标状态为 `failed`。

## 完整结果：两项确认要求通过一项

**700 名用户、14,000 个真实决策已全部收齐并审计。固定 20% Jev 融合相对
SASRec 的 AUC 增益得到支持，但未能确认它优于同权重的 MiniLM 语义对照。
本轮整体确认要求未通过，不能据此宣布 ParetoJev 项目达标。**

| 方法 | AUC | HR@5 | NDCG@10 |
|---|---:|---:|---:|
| 同训练用户的 item-CF | 0.703233 | 0.569349 | 0.489881 |
| SASRec | 0.779549 | 0.641429 | 0.533152 |
| MiniLM 单独排序 | 0.617669 | 0.427143 | 0.368567 |
| Jev 单独排序 | 0.669098 | 0.480476 | 0.430285 |
| SASRec + 20% MiniLM | 0.783083 | 0.649048 | 0.530522 |
| SASRec + 20% Jev | 0.785301 | 0.647381 | 0.539898 |

两项预登记主比较使用 Bonferroni 校正的 97.5% 双侧配对 bootstrap 区间：

| 主比较 | AUC 差值 | 97.5% 区间 | 下界 > 0 |
|---|---:|---|---|
| Jev 融合 − SASRec | +0.005752 | [0.000413, 0.011128] | 是 |
| Jev 融合 − MiniLM 融合 | +0.002218 | [-0.003459, 0.007895] | 否 |

“未确认优于 MiniLM”不等于证明两者等效。当前区间仍容许小幅负增益或正增益；
不能仅凭 Jev 的点估计最高就选择它为已验证的最佳方案，也不能追加用户直到区间
变正。开发集上 Jev 相对 MiniLM 的较大优势没有以同样幅度复现。

次要结果的区间为未校正的描述性 95%：Jev 融合相对 SASRec 的 HR@5 增量
+0.005952，区间 [-0.015476, 0.028095]；NDCG@10 增量 +0.006747，
区间 [-0.006109, 0.019414]，两项均不确定。相对 MiniLM，HR@5 点估计低
0.001667，NDCG@10 点估计高 0.009376，两项区间也均包含 0。

SASRec 相对同训练用户 CF 的次要 AUC 增量为 +0.076316，95% 区间
[0.055677, 0.097143]，支持保留更强行为基线。融合的绝对指标虽然超过旧
Phase A 数值门槛，但 cohort、方法与验收范围不同，不能替换旧协议的结论。
本轮只检验固定单目标融合，未训练或验证 full ParetoJev 多目标重排架构。

## 下一步判断

保持本轮结果不变，不在这 700 名用户上重新选择权重或改动验收标准。
目前有证据支持“加入 Jev 可小幅改善 SASRec 的 AUC”，但不足以证明它比已测试的
MiniLM 方案更值得采用。优先整理本地语义基线、可比的部署成本和真实多目标数据
接入条件，再决定是否值得扩大 Jev 使用或训练复杂的融合重排模块。

本轮没有未解决的外部输入阻塞。要进入原计划的真实多目标主实验，仍需实际的
多目标反馈、可用于内容判断的物品信息和对齐的真实决策信号；不能从 MicroLens
下一条观看标签制造长看、点赞等目标。

## 冻结规则

- 排除此前 400 名开发用户及 1,000 名 checkpoint 验证用户后，用 seed 20261011
  选定 700 名新评价用户。固定每人 5 条历史、1 个下一条观看正例和 19 个时间窗口候选。
- 当前 SASRec 与 item-CF 的训练都排除全部 2,100 名用户，剩余 57,145 名训练用户。
  SASRec 从随机初始化重训，不复用旧 checkpoint。
- 沿用开发阶段选出的结构、学习率 0.001 与固定第 15 轮；旧的 1,000 名验证用户仅作
  诊断，不能改变本轮训练轮数、方法或权重。
- 主比较：SASRec + 20% Jev 对比 SASRec；对比 SASRec + 20% MiniLM。
  权重指用户内平均名次融合，第二信号占 20%，不是概率校准或模型参数融合。
- 复用固定版本 MiniLM 的标题向量、同样的 5 条历史和最大余弦相似度。
- Jev 使用相同 AutoTrust JEV-27B 版本与逐候选 Noul(click) 提问。
  准备 14,000 个真实决策，一次一个请求、相邻请求启动至少间隔一秒。
- 请求尝试总预算跨进程累计为 14,000；发送前持久记录。失败、超时或被中断的
  请求也占预算，没有后台重试。模型版本变化、网络错误或并发写入均停止采集。
  预算耗尽但分数不齐时不得降低样本量或给出完整验证结论。
- 收齐所有用户、核对每个分数与真实原始响应后，才允许输出测试指标。
  不按中途结果提前停止、扩样、调权重、换模型或挑选用户。

## 样本量与验收

开发集上的 Jev 融合相对 SASRec 平均 AUC 增量约 0.007895，逐用户差值标准差
约 0.06608。按正态近似和两项比较的 Bonferroni 校正，200 用户检出同等增益的
概率约 29%，700 用户约 82%。这是依赖开发效果估计的规划近似，不是成功保证，
也不是“两项同时通过”的联合功效。

主指标为 AUC，两项固定比较各用 10,000 次逐用户配对 bootstrap 的 **97.5% 双侧区间**。
只有两项区间下界均 > 0 才通过本轮确认要求。HR@5、NDCG@10 等排序指标及其
95% 区间同时报告，但属于次要结果。

本轮目标配置为 [`targets_sasrec_confirmatory.yaml`](../../configs/targets_sasrec_confirmatory.yaml)。
它确认的是一个固定单目标融合规则，不能证明 full ParetoJev 的多目标架构有效，
不能改写旧的 5% 开发 gate，也不能直接替换原 Phase A 协议下的验收结果。

## 网络故障后的操作修订

首次采集在约 3,609.62 秒后遇到一次 `UNEXPECTED_EOF_WHILE_READING` TLS
连接中断，立即停止：177 名完整用户，3,545 个有效原始响应，3,546 次请求尝试。
逐条核对这些缓存后，确认都属于冻结输入及相同模型版本；未计算中途测试指标。
服务健康检查随后恢复正常，默认 HTTP 客户端重试次数确认为 0。

原注册把请求尝试上限设为恰好 14,000，失败一次就无法收齐 14,000 个决策。
因此另存并提交了 [操作修订](transport_amendment.json)，仅提供最多 20 次额外
网络故障尝试，总上限 14,020。原注册、700 名用户、模型、提示词、20% 权重、
指标和统计检验保持不变。这是事后记录的运输故障处理，不伪称原先已登记。

恢复程序只接受明确的超时或 TLS EOF，先检查服务恢复；不会跳过证书验证、
重试 HTTP 限流/权限错误或接受模型版本变化。每次恢复仍在首个错误处停止。
恢复入口为：

```bash
.venv/bin/python scripts/resume_microlens_confirmatory_transport.py
```

证据：[首次采集记录](initial_collection_report.json)、[错误](initial_transport_error.json)、
[部分原始响应审计](partial_response_audit.json)、[输入逐字节重建](prepared_replay.json)。

## 执行与重放

以下是首次执行各阶段的命令；本次训练和采集已完成，不应重复 `train`。
已有产物的离线复核只需 `audit`、`evaluate`、`replay`；有操作修订时，采集恢复
使用上一节的 transport 入口。所有命令在仓库根目录使用项目虚拟环境：

```bash
.venv/bin/python scripts/run_microlens_confirmatory.py train
.venv/bin/python scripts/run_microlens_confirmatory.py score
.venv/bin/python scripts/run_microlens_confirmatory.py audit
.venv/bin/python scripts/run_microlens_confirmatory.py evaluate
.venv/bin/python scripts/run_microlens_confirmatory.py replay
```

`prepare` 用于首次登记，拒绝覆盖现有注册。`train` 保护已经完成的训练报告。
`score` 按冻结的身份和逐条缓存恢复，每次运行保留独立耗时记录；原始采集成本不会
被零请求重放覆盖。`evaluate` 拒绝部分 cohort，`replay` 禁用网络并比较全部预测、
逐用户指标、区间和累计采集成本。

原始数据、prepared 数据、模型 checkpoint、MiniLM 向量和真实响应缓存是本机
忽略的大文件，源码 Git bundle 不包含它们。其路径和哈希写在
[registration.json](registration.json) 及各阶段产物中。

## 适用范围

这些用户没有参与过先前的评价，但其交互曾参与旧开发模型的训练；本轮已将他们
从当前模型训练中彻底排除并重训。这仍是同一公开数据集的回溯性用户留出，
不是全局时间留出、跨平台验证或完全新采集的数据。其他训练用户的交互时间可能
晚于测试事件。负候选是未观看物品，不是实际曝光后未点击的记录。仅运行一个训练
随机种子，统计区间条件于当前模型、候选采样和数据集。

若公共端点不可用，最小外部替代输入是这 700 名冻结用户、14,000 个候选对齐的
真实 Jev 分数，附用户/候选 ID、模型版本和请求协议溯源；不会用合成分数填补。
