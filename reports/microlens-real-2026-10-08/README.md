# 第一轮真实 MicroLens × Jev 试验

2026-10-08。**真实数据、真实外部推理；20 用户先导试验，未证明融合有稳定收益。**

## 已完成什么

- 从 [MicroLens 官方下载页](https://recsys.westlake.edu.cn/) 获取交互与英文标题 CSV。
  共 719,405 条交互、100,000 名用户、19,738 个视频。原始文件保留本地，SHA-256 已登记。
- 完成 200 用户、每人 20 候选、最近 5 条历史、时间窗 ±3 天的上游协议基线复现。
- 在调用 Jev 前固定随机抽取的 20 用户，共 400 个候选。候选顺序按固定 seed 打乱；
  逐候选请求不包含其他候选、当前标签或正例位置。
- 通过作者的 [JEV-27B 公开演示服务](https://huggingface.co/spaces/autotrust/JEV-27B-Demo)
  完成 400 次真实 Noul 判断，无用户密钥、无付费云服务、无模拟或替代分数。
- 每个响应均核验 `autotrust/JEV-27B` 和部署 revision
  `7ce153d6f7933769527939bcb92ec3f3d8292884`。这是 AutoTrust 模型的文本服务，
  **不是 TypeSafe 官方 Jev，也不是直接输入封面的 JEV-27B-VL 实验**。

调用方式是先做 1 次真实连通性验证，再缓存复用该响应并请求剩余 399 个候选。
仅一个请求并发，发起间隔至少 1 秒；无隐式重试。批量阶段耗时约 402 秒，0 个失败 slate。
服务端自报的 400 次模型推理时间合计约 73 秒；这不是我们控制硬件的 serving benchmark。
版本依据是端点返回及作者部署说明，没有取得服务端权重进行独立核验。

## 200 用户行为基线复现

| 方法 | AUC | HR@5 | NDCG@10 |
|---|---:|---:|---:|
| 历史热度 | 0.5047 | 0.230 | 0.2040 |
| 标题 TF-IDF | 0.6016 | 0.385 | 0.3667 |
| Item-CF | **0.7276** | **0.490** | **0.5032** |

Item-CF 和标题基线与上游模型卡的三位小数报告接近。这里保留上游候选顺序和
tie-jitter 规则用于复现；该表不包含 Jev。

## 20 用户真实 Jev 比较

以下所有方法使用同一个事先选定的 20 用户子集和相同的 400 个候选。
它不是上一张 200 用户表的同一评价总体，不能直接比较两张表的差值。

| 方法 | AUC | HR@5 | NDCG@10 |
|---|---:|---:|---:|
| Item-CF | 0.6500 | 0.500 | **0.5055** |
| Jev 标题判断 | 0.6289 | 0.400 | 0.3923 |
| 固定 50/50 排名融合 | **0.6895** | 0.500 | 0.4578 |
| 五折用户交叉验证融合 | 0.6237 | 0.450 | 0.4083 |

固定融合的 AUC 比 Item-CF 高 0.0395，但 95% 配对用户 bootstrap 区间为
**[−0.0816, +0.1684]**，包含零；NDCG@10 反而下降 0.0478，区间为
[−0.1636, +0.0702]。交叉验证融合的 NDCG@10 也较差。

Jev 在 2 名用户上将正确候选排进前 5，而 Item-CF 没做到；Item-CF 反过来补救了
4 名用户。说明两路排序存在差异，但不能由此断言某种融合策略已经有效。
事后用标签挑选每位用户表现更好的方法，HR@5 可以达到 12/20；这是诊断上界，
不是可部署方法或本项目取得的融合结果。

**结论：真实链路已经贯通，这次小样本没有建立稳定的融合收益。** 没有根据这些
测试结果更换用户、删除候选、修改问题或继续调权重。固定融合权重为 0.5；CV 权重只由
其他用户折选择。主研究的 200 用户目标保持 `not_evaluable`，即使某项先导指标过线也不能通过。

## 协议边界与验证

- Item-CF 共现统计排除了所有 200 名评价用户，训练用户交集为 0。
- 每个评价用户的 5 条历史均严格早于其目标观看时间。
- 其他用户的共现统计使用整个回顾性数据集；这不是全局时间切分的生产前瞻预测。
- 每组 1 个实际 next item 加 19 个采样替代项。替代项不是记录下来的未点击曝光，
  所以这些数值只支持相对排序评价，不能声称是校准后的真实 CTR。
- 有 1 条候选标题缺失，保持原样并记录；未因模型表现剔除任何样本。
- 当前只使用英文标题、历史和一个点击／观看问题，没有验证其他五个行为目标。
- 并列分数的排名归一化改为平均秩，避免人为把位置当成信息；通过排列不变性测试。
- Bootstrap 使用 5,000 次用户重采样，条件于已有 OOF 分数；没有在每次重采样中重训融合权重。
- **195 项测试通过**。重新执行打分产生 0 次 HTTP 调用，评分 JSONL 和 SQLite 缓存字节一致；
  从原始 CSV 重建候选与 Jev 输入也得到完全相同的 SHA-256。

## 文件与复现

- `registration.json`：原始来源、哈希、用户选择、候选顺序、方法和推理版本的预登记。
- `data_audit.json`：真实数据规模、历史边界、缺失内容与协议限制。
- `upstream_reproduction.json` / `baseline_200_users.json`：200 用户行为基线及区间。
- `scoring_initial_report.json` / `scoring_replay_report.json`：初次调用与零调用恢复的报告。
- `pilot_evaluation.json`：所有方法的指标、区间、CV 权重和互补性诊断。
- `verification.json` / `tests.txt`：实际验证证据。

原始 CSV 在 `data/raw/microlens/`；准备好的候选在 `data/processed/microlens-real*/`；
400 份原始请求与响应缓存、评分 JSONL 在 `artifacts/microlens-real-public/`。
这些数据和缓存均不进入 Git 或源代码压缩包。

在新 checkout 放入相同哈希的两份官方 CSV 后：

```bash
python scripts/prepare_microlens_public_probe.py
python scripts/score_microlens_public_demo.py
python scripts/evaluate_microlens_public_probe.py
```

当前机器的直接 HTTP 下载收到 403，已通过官方浏览器下载链接成功获取。下载入口
仍是官方源，没有使用未经核实的镜像。已存在的输入不会被准备脚本覆盖。
公开服务的可用性和部署版本可能变化；客户端会拒绝未知版本，不会静默换模型。
