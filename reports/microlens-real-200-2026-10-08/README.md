# 200 用户真实 MicroLens × JEV-27B 评价

2026-10-08。**完整评价已完成；轻量融合出现 AUC 增量，但预设研究目标仅通过 2/4。**

本轮从既定 20 用户试验扩展到原先固定的全部 200 用户，未改模型、问题、候选集合、
单用户候选顺序、融合规则或参数搜索范围。保留 400 条旧分数，新增 3,600 次真实请求。
行为基线是 item-CF；这轮没有训练真实数据上的 SASRec+MMoE 或神经 ParetoJev。

## 执行与真实性

- 原始数据：MicroLens 官方交互和英文标题文件；来源和哈希见 `registration.json`。
- 每名用户 5 条历史、20 个候选，合计 4,000 条逐候选 Noul 判断。
- 服务：[AutoTrust 作者公开演示端点](https://huggingface.co/spaces/autotrust/JEV-27B-Demo)。
  所有响应均声明模型 `autotrust/JEV-27B`、部署 revision
  `7ce153d6f7933769527939bcb92ec3f3d8292884`。这是文本版本，不是 TypeSafe 官方 Jev
  或原生封面图 JEV-27B-VL 复现；未访问后端权重独立验证。
- 输入、版本和协议在新增调用前冻结；注册代码提交 `0e57183`。
- 并发始终为 1，请求启动间隔至少 1 秒，新增调用耗时约 3,619 秒（60.3 分钟）。
- 180 组新增用户全部完成，0 个失败 slate。20 组旧数据的请求内容和候选顺序逐项一致。
- 所有 4,000 个最终分数都逐条匹配其原始请求和缓存响应；没有模拟值、补值或模型替换。
- 恢复执行新增 HTTP 请求为 0，评分文件和原始缓存字节一致。

## 预登记主结果：同一组 200 用户

| 方法 | AUC | HR@5 | NDCG@10 |
|---|---:|---:|---:|
| Item-CF | 0.6876 | 0.540 | 0.4934 |
| Jev 标题判断 | 0.6476 | 0.460 | 0.4018 |
| 固定 50/50 排名融合 | 0.7079 | 0.540 | 0.4712 |
| 五折用户交叉验证融合 | **0.7274** | **0.570** | **0.5188** |

CV 在其余用户折选择权重，再应用于未参与选权重的用户折。五折的 Jev 权重分别为
**0.05、0.05、0.20、0.05、0.05**。没有用完整测试集挑选一个最好权重。

CV 融合相对 Item-CF 的配对用户 bootstrap（5,000 次）结果：

| 指标 | 绝对差值 | 95% 区间 |
|---|---:|---:|
| AUC | +0.0397 | **[+0.0061, +0.0742]** |
| HR@5 | +0.0300 | [−0.0100, +0.0700] |
| NDCG@10 | +0.0254 | [−0.0052, +0.0575] |

这支持当前协议下的 AUC 增量；HR@5、NDCG@10 的改善仍有不确定性。固定 50/50
融合的 AUC 区间跨零，且其 NDCG@10 下降，不能把任意混合都视为有效。

## 新增 180 用户的独立检查

此处使用相同的全体 OOF 预测，仅分组统计，不为这 180 人重新选择参数。

| 方法 | AUC | HR@5 | NDCG@10 |
|---|---:|---:|---:|
| Item-CF | 0.6918 | 0.5444 | 0.4920 |
| Jev | 0.6497 | 0.4667 | 0.4029 |
| 固定融合 | 0.7099 | 0.5444 | 0.4727 |
| CV 融合 | **0.7301** | **0.5722** | **0.5240** |

新增人群的 CV AUC 增量为 +0.0383，区间 [+0.0023,+0.0751]；方向与全部 200 人一致。
它不是额外的独立训练实验：CV 权重仍来自全体数据的既定用户折，bootstrap 也没有
在每次重采样中重拟合权重。

## 为什么 Item-CF 与之前复现的 0.7276 不同

之前的上游复现将正例固定放在第一个候选位置，并添加同一组按位置固定的微小噪声
来打破并列。本轮沿用先导试验的预登记随机候选顺序，消除了正例固定位置的信息。
**用户、候选、标签和 Item-CF 原始分数均未改变**，已按 `(user,item)` 逐项核验。

由于 131/200 名用户的正例与其他候选具有相同 Item-CF 分数，AUC 对这种并列处理敏感。
旧的 0.7276 是原协议复现值，不能直接拿来作为本轮的同口径行为基线。

为核查增益是否只是规则造成的，完成主评价后额外计算了通常的 AUC：正例分数更高记
1 分，并列记 0.5 分，不加噪声。该诊断**不替换预登记主结果或目标判定**。

| 方法 | 并列计半分的 AUC |
|---|---:|
| Item-CF（原顺序与随机顺序完全一致） | 0.6955 |
| Jev | 0.6475 |
| 固定融合 | 0.7084 |
| CV 融合 | **0.7272** |

CV 增量仍为 +0.0317，区间 **[+0.0068,+0.0572]**。因此 AUC 增量没有在常规并列定义下消失。
后验分组显示，收益主要集中于正例行为分数存在并列的 131 名用户；其 AUC 从 0.5392
到 0.5892。无此类并列的 69 人从 0.9924 到 0.9893。98 人的正例 Item-CF 分数为零；
这表示缺少共现区分力，不能直接等同于全局冷启动物品。

这提示一个更具体的假设：**以较小权重使用 Jev，可能帮助行为模型区分同分候选。**
它来自事后诊断，后续应在新的独立人群验证，不能在这 200 人上继续调参来证明它。

## 预设目标

| 必需目标 | 阈值 | 实测 | 判定 |
|---|---:|---:|---|
| CV AUC | ≥0.735 | 0.7274 | 未通过 |
| CV HR@5 | ≥0.600 | 0.5700 | 未通过 |
| CV NDCG@10 | ≥0.510 | 0.5188 | 通过 |
| 配对 AUC 增量区间下界 | >0 | 0.0061 | 通过 |

Target Mode 现在有完整真实证据，状态是 **failed（2/4）**，而不是先导阶段的
`not_evaluable`。工程执行成功与研究目标全部达标是两个不同结论。

## 证据、限制与复算

- `registration.json` / `preflight.json`：扩展前冻结的设置、输入哈希、复用和调用预算。
- `run_registration.json`：实际执行的配置与代码来源。
- `scoring_initial_report.json` / `scoring_replay_report.json`：真实请求与零请求恢复。
- `score_audit.json`：4,000 个分数与原始缓存响应逐项一致的证明记录。
- `evaluation.json`：完整主结果、新增人群、CV 权重、置信区间及目标报告。
- `tie_diagnostic.json`：明确标记为后验的并列敏感性诊断。
- `verification.json` / `tests.txt`：测试和复算验证。

数据与原始响应缓存仍留在本地，未放入 Git 或源代码包。已有完整工作区可离线复算：

```bash
python scripts/score_microlens_public_demo.py \
  --registration reports/microlens-real-200-2026-10-08/registration.json \
  --input data/processed/microlens-real-200/jev_input.jsonl \
  --output-dir artifacts/microlens-real-public-200
python scripts/audit_microlens_public_scores.py
python scripts/evaluate_microlens_public_probe.py \
  --report-dir reports/microlens-real-200-2026-10-08 \
  --score-dir artifacts/microlens-real-public-200 \
  --candidates data/processed/microlens-real-200/candidates.csv
python scripts/diagnose_microlens_ties.py
```

第一条命令会跳过全部已完成用户，已实测产生零 HTTP 请求。新的在线实验需另建注册，
并核验服务版本，不能覆盖已有数据。原始缓存缺失时，仅有源码无法保证重现外部服务
某次历史响应；当前本地工作区已保存完整缓存。

研究限制仍包括：只有标题输入；11 条候选标题缺失且未事后删除；负例是采样替代项而非
已观察未点击曝光；item-CF 使用其他用户全期历史，非全局时间因果预测；模型预训练数据
未独立核验；置信区间条件于已有 OOF 分数；尚未验证六目标 ParetoJev、真实冷启动增益
或服务延迟。没有把当前轻量融合结果归功于尚未进行真实训练的神经重排框架。
